## B52 — P1 candidate — Expo startup trusts cached identity and role after server rejects or cannot verify account, unlike web

**Product impact:** When a previously signed-in user's account has been disabled, revoked or its privileges removed, a relaunch of the Expo app can briefly or persistently show the cached identity and role-based navigation even though the server no longer authorizes the account. If the current access JWT still has a future `exp`, its validity check is local until API communication; a `/users/me/` 401/403 may be swallowed and the cached user reinstalled as signed in. This is a user-facing misleading authorization/session state, **not proof the backend serves restricted data**.
