Touch `frontend_mobile/features/explore/ArticleDetail.tsx`, optionally a native `ArticleCommentThread.tsx` UI component; no new API function. **Executable fail-today test:** mount production `ArticleDetail` with a root `reply_count:2` and transport spy; tap "View 2 replies", expect `listArticleComments(slug,{parent:id,page:1})` then rendered child reply; current screen has no button or `parent` read and fails.

Touch `frontend_mobile/app/explore/hubs/post/[id].tsx`; existing `publicContent.listPostComments(id,{page})`. **Executable fail-today test:** render production native detail with page 1 `{results:[a],next:'...'}`; tap "Load more comments", expect second shared-core query with `page:2` and both comments visible, error preserving first page. Current implementation exposes no load-more affordance and fails.
