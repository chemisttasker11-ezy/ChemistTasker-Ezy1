## B63 — P1 conditional — Native-kiosk pairing authorization can be redeemed as web-online by declaring a non-native platform

**Route → authorization → credential/storage.** Manager requests a pairing code through [kiosk_api.py:85-163](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance/kiosk_api.py#L85-L163). Durable `KioskPairingAuthorization.allowed_client_kind` defaults to `NATIVE_OFFLINE` ([models.py:75-115](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance/models.py#L75-L115)). Public redemption accepts **untrusted** `platform`, `public_signing_key`, `client_attempt_id`, `proof_signature` ([kiosk_api.py:164-207](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance/kiosk_api.py#L164-L207)). `redeem_kiosk_pairing_code` declares a request `native` only when the caller-supplied platform is windows/macos/linux, requires Ed25519 proof only then, and checks `authorization.allowed_client_kind` **only if native**, meaning a caller with the valid code may redeem the same authorization as `WEB_ONLINE` without proof ([credentials.py:368-468](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance/credentials.py#L368-L468)). `activate_kiosk_device` accepts the supplied `client_kind` and stores it in `KioskDevice` ([credentials.py:134-170](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance/credentials.py#L134-L170)). Successful web token can authorize online PIN/QR endpoints via device-token verification ([kiosk_api.py:389-500](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance/kiosk_api.py#L389-L500)).

**Threat caveat:** The six-digit code remains required, securely generated, single-use and globally rate-limited; an attacker is **not** shown to brute-force or obtain a code. Legacy/web redemption without a native platform is explicitly expected by [test_kiosk_pairing_code.py:186-213](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance_tests/test_kiosk_pairing_code.py#L186-L213). This is a **conditional policy mismatch** only if native-offline authorizations are intended to be restricted to signed native devices. Do not claim proof bypass for signed *offline* events (the offline sync explicitly checks `NATIVE_OFFLINE`). 

**Negative test:** Create a manager-issued authorization with allowed kind NATIVE_OFFLINE and attempt public redemption with `platform='web'`, no signing key, known valid code. Expected under strict native-only policy: reject without consuming authorization or issuing kiosk device token. **Positive:** genuine Windows Ed25519-bound redemption succeeds once; retry with same attempt/key follows documented recovery; a *separately explicitly web-authorized* token may pair web legacy terminal. Test unauthorized and expired code. No runtime run.

Existing [test_kiosk_pairing_code.py:143-170](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/attendance_tests/test_kiosk_pairing_code.py#L143-L170) explicitly asserts raw pairing code in durable notification: regression is an intentional test change requiring product policy.
