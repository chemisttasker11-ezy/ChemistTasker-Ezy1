The Payment table preserves these rows [worker_finance/models.py:L76–L102](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/worker_finance/models.py#L76-L102), and the response directly subtracts them from revised payable [worker_finance/services.py:L808–L839](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/worker_finance/services.py#L808-L839). **Tests:** [tests/test_api.py:L147–L160](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/worker_finance/tests/test_api.py#L147-L160) rejects an overpay *when creating a payment* and [tests/test_api.py:L191–L239](https://github.com/chemisttasker11-ezy/ChemistTasker-Ezy1/blob/b77e9fd296bc2710350ef6f3cd402ce2529ffc06/backend/worker_finance/tests/test_api.py#L191-L239) deliberately tests editing a marked-paid invoice; neither guards a later downward revision.
